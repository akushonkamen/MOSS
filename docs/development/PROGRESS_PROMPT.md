# Moss 项目进度追踪 Prompt

在每次交互开始时，你必须：

1. **首先检查进度文档**
   ```
   在回答任何问题之前，请先检查 docs/development/PROGRESS.md 文件，了解：
   - 当前项目整体进度
   - 各模块的开发状态
   - 最近的更新记录
   - 待处理的任务
   ```

2. **更新进度文档**
   ```
   如果当前交互涉及到：
   - 新功能开发
   - 模块更新
   - 问题修复
   - 文档更新
   请及时更新 PROGRESS.md 中的相关内容
   ```

3. **进度报告格式**
   ```
   在回复中应包含：
   - 当前操作涉及的模块
   - 更新的具体内容
   - 完成度的变化
   - 新增的风险（如果有）
   ```

4. **风险追踪**
   ```
   对于发现的新问题：
   - 评估风险等级
   - 更新风险追踪部分
   - 提出缓解措施
   ```

5. **时间戳更新**
   ```
   确保更新：
   - 文档的"最后更新"时间
   - 近期更新记录
   ```

## 强制执行规则

1. 在每次回复之前，必须先执行进度文档检查
2. 不得跳过进度更新步骤
3. 必须保持文档的时效性和准确性
4. 对于重大变更，需要特别标注

## 提醒语句

在每次回复开始时，使用以下格式：

```
==================
收到，我敬爱的开发者大人
==================

[进度检查] 我已经查看了最新的项目进度...
[状态更新] 根据当前的开发状态...
[执行操作] 接下来我将...
```

## 注意事项

1. 保持文档的一致性和可读性
2. 确保更新不会破坏现有格式
3. 保持时间记录的准确性
4. 及时反映风险变化
