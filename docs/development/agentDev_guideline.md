## 1. 设计目标

- **单一数据源**：agent 只能接收和处理来自上游输入的信息，禁止混入任何外部信息或额外指令。
- **行为确定性**：agent 的行为和输出应完全由上游输入决定，保证结果的可控和可复现。
- **安全隔离**：确保 agent 不会因为外部干预而改变预定工作流程或逻辑。

---

## 2. 基本原则

### 2.1 仅依赖上游输入
- **输入限制**：prompt 设计时应明确说明“只处理上游输入”，不允许 agent 从其他途径（例如外部文件、隐含知识库之外的额外指令等）获取信息。
- **输入格式标准化**：规定上游输入的格式、语法、数据结构等，确保 agent 可以准确解析和处理。
  
### 2.2 明确定义任务
- **任务说明**：在 prompt 中详细说明需要完成的任务，但任务描述必须嵌入到上游输入之中，而非单独作为 prompt 附加说明。
- **示例模板**：可以提供典型的输入/输出示例，让开发者和测试者明确预期行为。

### 2.3 严格执行上下文隔离
- **上下文限定**：在 prompt 的开头部分增加“上下文声明”或“工作范围说明”，例如：
  > “请注意：以下内容均来自上游输入。请严格按照上游输入的信息执行任务，不允许引入其他任何外部信息。”
- **禁止拓展**：明确指出 agent 不得自行拓展任务范围或引入额外信息。

### 2.4 日志与监控
- **输入日志记录**：记录每次调用时 agent 接收到的上游输入，便于后续验证 agent 是否严格按照输入执行任务。
- **异常监控**：设定检测机制，当 agent 输出偏离预期（例如引入未授权的信息）时能够及时报警或回滚。

---

## 3. 开发与测试流程

### 3.1 开发阶段
- **模板建立**：开发一个标准 prompt 模板，模板中预留上游输入插槽，并内置必要的行为约束语句。
- **代码评审**：在 prompt 开发过程中进行代码（或文本）评审，重点检查是否存在可能绕过上游输入约束的描述。

### 3.2 测试阶段
- **单元测试**：编写单元测试，输入各种格式和边界情况的数据，验证 agent 是否严格按照上游输入完成任务。
- **回归测试**：在每次更新 prompt 逻辑后进行回归测试，确保新增内容不会破坏“只依赖上游输入”的设计原则。
- **安全测试**：模拟异常或恶意输入，确保 agent 不会接受外部干预或执行超出预期范围的操作。

---

## 4. 示例模板

```plaintext
【Agent Prompt 开始】
【注意】本次任务的所有信息均来自上游输入，请严格根据以下内容执行操作，不得引入任何其他信息。

【上游输入开始】
{在此处插入由上游系统提供的输入数据，格式必须符合预先定义的标准}
【上游输入结束】

【任务说明】
请根据上游输入中的信息执行以下任务：
1. 分析输入数据，提取关键要素。
2. 根据关键要素生成对应的处理方案。
3. 输出详细步骤及最终结果。

【Agent Prompt 结束】
```

---

## 5. 文档与版本管理

- **文档记录**：所有 prompt 的开发规范、模板、测试用例和评审记录都应存档，便于追溯和维护。
- **版本控制**：采用版本管理系统（例如 Git）对 prompt 模板进行管理，每次修改需记录修改原因和测试结果。
